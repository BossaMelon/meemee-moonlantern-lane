# 咩咩与月灯巷

**MeeMee & Moonlantern Lane**

为咩咩制作的单人魔法料理饭店经营游戏，以《哈利波特》为背景。采购食材、备料、用魔法烹饪和出餐，熟悉的 HP 角色偶尔带来特殊点单或短委托。所有开发工作由 agent 完成，游戏运行时不需要大模型。

## 当前状态

2026-10-25：已保留初步研究与设计，源码仓库现为 public；工程 harness 已验收合并，产品已转向魔法料理饭店；正在保留通用核心、UI、像素美术与原型 CI，等待 H02 冻结三日料理设计和验收。开发基线选用 Godot 4.7.2 标准版、GDScript 和 Compatibility 渲染器；本机引擎实际报告 `4.7.2.stable.official.ed1daf0bf`。

**目前尚无已交付的可玩入口，三日原型仍在实现，未进行人类试玩或发布。** 实际进度、证据和风险以 [项目状态](docs/project-status.md) 为准。

最先在当前 Mac 上交付可打开的原型；最终目标为 Windows 和 iOS，触屏与手柄从原型阶段纳入。2D 表现采用原创像素美术、固定三分之四斜俯视的小店，通过环境、角色、厨房和菜品行为构建可信的魔法世界；先完成三日循环，不先制作大世界。

## 首个可玩交付

原型必须连续经营三日，覆盖采购、备料、魔法烹饪、出餐、结算、升级、次日，以及暂停、保存和重启恢复。快餐小食与热食炖锅等路线须有实际行为差异；厨房奇物设备保留留用/出售取舍，预告雨天暖身或保温需求。最小菜谱、日程和验收由 H02 在 `docs/05-restaurant-prototype.md` 冻结，当前尚未完成料理实现。

魔法进入烹饪和菜品行为，而非只换名称。熟客先做一位的偶发可选短委托，优先海格巡护带餐、两种料理解法；不扩展大地图或长剧情。

已知菜谱默认支持批量制作。基础食材供货不能靠随机抽取卡进度。正确性与可运行性由测试、经济模拟和实际截图验收；是否让咩咩主动想“再营业一天”仍须人类试玩。

## 开发与检查

先读 [AGENTS.md](AGENTS.md) 与 [开发接手说明](docs/03-agent-handoff.md)。实施只在可见独立 chat 中进行，禁止 sub-agent；仅总协调拆派任务。模型与推理强度按任务清单指定，全部使用 Standard。每个实施 chat 在隔离工作树和任务分支开发、提交 PR，由总负责人验收合并；共享 checkout 保持 `main`。

统一检查入口为：

```sh
python3 tools/gate.py --stage harness
python3 tools/gate.py --stage prototype --godot /absolute/path/to/Godot --report output/prototype-gate.json
```

这两个命令定义检查契约；`prototype` 在游戏或必需用例不存在时必须失败，`harness` 通过不能宣称游戏完成。Mac 源码启动器由工程 PR #7 提供，待该 PR 与 UI 主场景集成后使用 `./tools/启动月灯巷.command`；它依赖本地 Godot，不是独立导出的应用。实际可玩状态见项目状态，无需用户手动搭场景。

## 历史与边界

项目最初仅交付探索文档，当时未实现游戏、未选引擎，曾建议浏览器原型。后续用户已授权持续实现，并明确 Windows、iOS、触屏与手柄；当前技术决定替换原来的浏览器优先建议。

用户已确认采用《哈利波特》背景和 HP 熟客，经营主体改为魔法料理饭店。角色以新绘制的原创像素表现呈现，不使用电影截图；停止旧文具家居商品扩充。旧 catalog 测试仅作为通用底座证据，不能证明新料理产品完成。未授权购买资源、开付费服务或对外发布游戏。
