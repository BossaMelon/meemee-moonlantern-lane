# 三日魔法饭店：实现契约

本契约取代旧奇物杂货、文具/家居路线。题名保留：咩咩在对角巷附近的月灯巷开一家小饭店。允许《哈利波特》同人地点和人物；全部画面为原创统一像素，三分之四斜俯视、隐藏屋顶、全店总览。先交付 Mac 单人离线三日与保存恢复，包含一个约 2–3 分钟的可选动作采集小场地；不加大地图、独立烹饪小游戏或长剧情。Windows、iOS、实体手柄另验；运行时无 LLM。

这是待实现的规则，数值是待五种子模拟及试玩验证的初值，不是平衡结论。任务/状态只在既有台账记录。验收 ID 以 [原型契约](../contracts/prototype-v1.json) 为准，策略与边界输入见 [夹具](../tests/fixtures/prototype-scenarios.json)。

## 2. 采购、备餐、菜单与升级

每日 `shopping → preparation → trading → closing → settled`，前两日 `next_day` 继续，第三日提供结束/保存。采购阶段可插入一次 `shopping → expedition → shopping`，不参加也能经营。UI 称采购、探险、备餐、营业、收工、日结。先读需求与预告，再囤食材；已知菜谱一键制作 N 份，立即完成，不用真实等待。每份按实际消耗食材成本入账。

`display` 把已备好的份数移到菜单可售库存，`undisplay` 移回储藏；菜单初始 2 个菜品槽，按菜品种类而非份数占槽。营业只消耗菜单实际份数，不按点击次数凭空出菜，原料不能在营业中自动变成菜。普通客自动成交；不强制逐客收银。营业结束未售份数回储藏，食材和菜均跨日保留，三日切片不加腐败系统或退出惩罚。UI 分开显示储藏食材、备好份数、菜单剩余和厨具槽。

升级共三项，日结后购买，次日生效：`supply_pass` 暖焰草供货契约（20），开放稳定新食材与暖焰汤选择；`shelf` 扩展菜单（24），同时供应第三道菜、减少撤菜换菜单；`field_kit` 探索套装（24），取得下节的新武器/技能，另要求累计菜品销售收入至少 24，厨具回收或恢复所得不算。轨迹必须用实际经营收入完成投资并使用新选择，不能仅增加售价。初始现金 60、遗留坩埚 1 件、总库存容量 80、基础食材各日保证至少 12 份，解锁后的暖焰草也至少 12；种子可改变额外 0–2 份及客人顺序，不影响基础可达性。原料购入和奖励都计入容量。

价格档沿用 `friendly/standard/premium = 90/100/115%`，正整数四舍五入。第三日符合 `warming + heat_hold` 的菜获得雨天 25% 加成，上限 25%，仍受客人预算约束。日费 `min(4, cash)`。`recover` 为采购阶段每日一次零成本「帮邻店洗锅」获得 12，足够重新采购并批量做浮空饼；记录次数，读档不能刷新。`recycle` 除坩埚固定 18 外均为非装配库存按成本半价售回；回收与菜品销售分开记账，不能用免费遗留设备售款充当料理毛利。初始坩埚的取得来源/数量与成本可追溯，不可重复领取。

## 3. 三日需求与海格

每日 6 名普通客：3 名赶路客要求 `meal + quick`，3 名正餐客要求 `meal + hearty`；各自预算为固定种子下 23–30，顺序可变。两路线允许放弃不匹配客人，必须记录原因，不要求每单都成。每日再有一笔停时、可拒绝的特殊需求；整个需求板在采购前可读。

第二、三日额外各 1 名照路外带客要求 `meal + trail_light`，预算 30；只由星火暖焰汤满足。第三日另有 1 名庆功客要求 `meal + celebration`、预算 40，只由彗星馅饼满足；第二日前可读此预告及精英材料来源。没探险可正常放弃，不影响主线。战斗食材改变真实匹配，不仅改变售价；同时增加可计划的次日需求。

| 日 | 特殊需求（预算） | 当日可验证的选择 |
|---|---|---|
| 1 | 赶路巫师的外带小食：`meal + quick + portable`（30） | 浮空饼；开张先体验批量备餐与自动送餐，遗留厨具留用或售回均可继续 |
| 2 | 海格「巡护带餐」：`meal + warming + heat_hold + portable`（30） | 暖焰汤或自搅炖锅；一份即完成，奖励 2 份 `ember_herb`，回到既有菜谱，不开新系统 |
| 3 | 雨天返程客：`meal + warming + heat_hold`（30） | 供货契约后采购草煮汤，或首日保留坩埚用基础南瓜/奶油做炖锅；两条来源都稳定 |

海格只在第二日固定来访一次；订单 ID `d2-hagrid-patrol`、`character_id=hagrid`、`quest_id=hagrid_patrol`，从 pending 到成交/拒绝记录都保留身份。UI 显示原创像素海格形象、姓名、需求、预算、奖励与「交付/跳过」。停时可查看菜单；不增对话树。完成时一次原子提交：消耗菜单中 1 份匹配菜，收取实际价格、奖励 2 份草、标记完成。容量不足以接收奖励时整笔拒绝并说明原因；可以跳过继续，不能吞掉奖励或重复发奖。奖励按零取得成本入账并单列数量，不是营业收入。

跳过海格没有罚款、不锁菜谱/供货/第三日；供货契约从一开始可自主购买。待处理、完成、跳过和发奖标记及相应人物信息均保存；同请求、换请求重交、读档重交都不重复获利。海格没有来访的存档不能凭空完成任务。

最迟第二日采购前，`forecast` 必须写明第三日雨天、必需标签和上述两种解法各自的材料、设备/升级前提及稳定来源。准备与不准备使用同种子分叉；未准备不送匹配菜或奖励。事件可跳过但不等于可以省略实现或验收。

## 4. 一小段真实动作采集

每日采购时可进入「巷后菇圃」一次。进入前显示食材、剩余次数、退出/失败规则；开始即持久化扣除当日次数，重复点击或读档不重开。目标体验 2–3 分钟，主动提前结束不罚款，不强等。场地边界 960×540 逻辑单位；第一日三只星火菇怪，第二日四只，第三日三只加一只月心菇精英。同场地换配置，不开新地图。玩家实际移动、瞄准施法、闪避，敌人提前显示方向/范围再攻击。必须有位置、碰撞、攻击命中和击败状态；不得用抽签、菜单判定或一键获胜代替。

可调整初值：玩家 3 生命、速度 160/s；施法发射速度 360/s、射程 300、冷却 0.5s、一次命中伤害 1；闪避速度 300/s、持续 0.2s、冷却 1.2s、期间免伤；敌人 2 生命、0.6s 预警后沿锁定方向冲刺，碰撞伤害 1、两次攻击间隔至少 1.5s，同次攻击不可每帧重复伤害。动作目标需适配等价逻辑坐标；UI 动画不决定命中。普通时钟最大 180s，击败全体并拾取掉落、到入口退出、主动撤退或生命为零均返回采购；离线/暂停不耗时。此时间上限是一次可中断玩法长度，不是等待要求。

成长必须在三日中实际发生：初始武器 `bolt_wand` 是上述直线长射程魔杖；第一日日结用营业收入买 `field_kit`，第二日取得 `fan_wand` 与技能 `gust`。`fan_wand` 每次沿瞄准方向 -20/0/+20° 发三弹，射程 180、冷却 0.8s，同次施法对同敌至多伤 1，区别在短程覆盖而非简单加伤。`gust` 为独立按键的半径 120 推退脉冲，推开敌人 80 单位、冷却 3s，无直接伤害；可打断冲刺预警并令护盾精英暴露 1s，不能取消已经发出的环形波。武器仅采购阶段装备/切换，取得不自动抹掉旧武器；基础施法、闪避、新技能可组合使用。

第三日精英 4 生命，正面 120° 护盾挡弹；交替使用 0.8s 扇形冲刺预警与 1.0s 环形波预警，冲刺结束后暴露 1s。玩家可绕后、等破绽、用 gust 打断后接射击或闪避穿过波；需要位置和时机，不仅增加血量/改色。精英击败生成唯一 `moonheart`，当天回店实际做彗星馅饼并满足庆功客。基础武器仍可通过走位击败，成长提供新打法，不随机锁进度。武器造型、技能推退、精英护盾/预警需各有可读视觉。

每只普通敌人首次真正击败时在其位置生成 1 份 `sparkcap`，精英只掉 1 份 `moonheart`，靠近拾取，ID 为 `day + expedition_id + enemy_id`；生成/拾取/入账各不可重复。最后一只击败后先进入可移动拾取的 `cleared` 状态，拾取全部掉落或主动离场才结束，避免最后掉落不可取得；180s 上限仍适用。容量满时掉落留在场上并解释，不能丢货后记已领取；离场未拾取物明确放弃且不能重开刷取。失败/撤退保留已拾取材料，无罚金、债务、清档或基础供货锁。存档完整保存位置、生命、武器所有权/装备、新技能、待生效升级、敌人预警/护盾/攻击阶段、弹体、冷却、已收集掉落、随机状态、剩余时间及 50ms 固定步的余数；恢复继续原位置和时刻。

`floating_pie` 也能在采购阶段从储藏吃掉一份，取得下一次探险抵消一次伤害的「轻羽护盾」。只允许一个待用护盾，不叠加，已有时再次吃应原子拒绝；食物真实消耗且不获得售价。进入探险把待用护盾移入本次战斗，首次本应受伤时消耗，离场未用也不退回。常规循环为：第一日探险材料 → 第二日汤变体/照路客 → 收入购买基础食材并留一份饼 → 第三日吃饼护盾探险。保存/恢复不得复制菜或护盾。不探险分支仍可完整三日。

## 5. 两路线与接口复用

- `quick_service`：首日售回遗留坩埚，以浮空饼批量周转，日结投资 `supply_pass`，第二日开始汤/饼双菜单。取舍是获得 18 现金用于食材/供货，放弃无设备无法制作的炖锅与正餐客。
- `hot_meals`：首日保留并安装遗留坩埚，备炖锅与少量浮空饼，优先正餐客；放弃立即售回的 18。雨天可用基础供货做炖锅；后续投资供货/第三菜单增加选择。

以上均在相同五种子三日完成、累计实现毛利为正、不靠应急恢复；不是两套固定脚本假装策略。还运行保守周转、厨具投资、雨天备货三策略。报告期末现金/分项库存、成本/收入/毛利、升级日、成交/失败原因、恢复次数、动作轨迹；评估差异，不声称已证明好玩。

复用基线为 core `8b407192df979bad43273e78c4ab837e3e754d82`：`command(kind,args,request_id)`、`view()`、`snapshot()`、`advance()`、暂停和保存/恢复的外层形状保持，原有阶段保留并增 `expedition`。`buy/craft/display/undisplay/install/uninstall/price/open_shop/fulfill/decline/settle/upgrade/next_day/recover/recycle` 参数沿用；`fulfill {order_id,item_id}` 仍为一份，批量只作用于 `craft`。ID 使用上文料理 ID，禁止沿用笔/灯 ID 冒充菜。
